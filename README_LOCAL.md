# RLTTTSK — локальная версия с просмотром лотов

Инструкция для готового локального ZIP-пакета от 02.10.2026. В GitHub хранятся исходники; большая SQLite-база, результаты QA и присланные CSV остаются в локальном пакете. Чтобы запустить проект из GitHub checkout, сначала соберите данные по инструкции в основном README.

## Быстрый запуск
- В готовом ZIP на macOS: откройте «Запустить RLTTTSK.command».
- Либо из корня выполните: node scripts/serve-local.mjs
- Откройте http://127.0.0.1:8765
- Нужен Node.js 24 или новее. Интерфейс, собранный Worker и SQLite входят в пакет.
- Установка npm-пакетов для готового пакета не нужна. Остановка сервера: Ctrl+C.
- Это локальный адрес. Публикация исходников на GitHub сама по себе не обновляет данные публичного Worker.

## Как загрузить ваши CSV
Во вкладке «Список закупок CSV» добавьте CSV извещений и ТРУ. Можно выделить
несколько файлов за один раз, добавлять их по одному в любом порядке или
перетаскивать на поле загрузки. Если сначала добавить только ТРУ, сайт соберёт
временные лоты по lot_id и названиям позиций: их можно просмотреть и запустить
подбор, но бюджет и заказчик останутся неизвестными. Когда добавите извещения,
эти лоты дополнятся их точными полями. Выбранные файлы видны списком;
каждый можно убрать или очистить набор. Связь таблиц — по lot_id.
При добавлении новых CSV ранее полученные результаты сохраняются для лотов,
у которых запрос и состав ТРУ не изменились. Изменённые лоты требуют нового подбора.
После обновления страницы результаты сохраняются, но файлы нужно выбрать заново,
если требуется дополнить набор.
- input_samples/test: purchases_1.csv — извещения, purchases_2.csv — ТРУ.
  Проверено: 38 лотов, 670 позиций ТРУ.
- input_samples/final: все 8 файлов. purchases_1…4.csv — извещения,
  purchases_5…8.csv — ТРУ. Проверено: 99 лотов, 1 468 позиций ТРУ.
- Исходные CSV из присланных ZIP тоже поддерживаются. ZIP сначала распакуйте.
- Лимит: 200 извещений, 12 файлов, 5 МБ на файл / 20 МБ на набор.
  Строки ТРУ в лимит 200 не входят.
- Поддерживается UTF-8 и Windows-1251.
- Финальный файл со склеенным заголовком reqnum;procedure_name исправляется
  только при однозначной структуре строк; на экране появляется уведомление.
- Слева — lot_id, фильтр и статусы; справа — параметры лота, ТРУ и рекомендации.
- Можно выбирать конкретный номер, нажимать «Предыдущий / Следующий»,
  подбирать один лот либо весь список.
- ИНН заказчика ведёт к поиску в ФНС и ЕИС. Ссылки открываются по нажатию,
  а не считаются подтверждением конкретной карточки или публикации в ЕИС.
- Карточка поставщика открывается нажатием по всей площади. Кнопка
  «Где встречался поставщик» раскрывает до шести реальных записей лотов
  из архива по выбранному разделу ОКПД2: дата, предмет, канал, ИНН заказчика
  и начальный бюджет, если он прошёл проверку диапазона.
- Для ЭМ показан статус из is_winner; для АИС ГЗ — нейтральная запись
  о поставщике. Примеры не являются полной историей участия.
- Результаты сохраняются при переключении лотов и в этой вкладке после обновления страницы.
- Выгрузка содержит все лоты, исходные поля, ТРУ, рекомендации, контакты и статусы.
  Ошибочные и остановленные строки не исчезают.

## Что означает «Предложенные поставщики»
Это рекомендации нашего сервиса. В двух присланных архивах есть извещения и ТРУ,
но нет таблицы заявок, участников или коммерческих предложений.
Сайт не выдаёт рекомендации за фактических участников, победителей или их цены.

## Контакты и ценовые данные
- В карточках видны опубликованные телефон, email, сайт, источник и дата проверки.
- Для компаний без контактов есть ссылка поиска по ИНН; значения не выдумываются.
- Контакты дополнены по официальному списку GE HealthCare и совпадению ИНН:
  https://www.gehealthcare.ru/about/partners-list
  Источник прочитан 02.10.2026. Всего в локальном контактном файле 7 компаний.
  Это опубликованные контакты; отвечаемость телефонов и доставляемость email не проверялись.
- У соответствующих компаний показана роль «Дистрибьютор GE HealthCare» со ссылкой
  на источник. Для остальных роль требует подтверждения.
- Рядом показаны бюджет своей закупки и ценовая информация поставщика.
- Актуальная цена: «По запросу», потому что коммерческих предложений в данных нет.
- Исторический ориентир — исходное поле start_price похожего извещения,
  с датой, lot_id и предметом. Это не цена единицы и не предложение компании.
- Рубли приняты как валюта российского закупочного архива; отдельного поля валюты нет.
- Объёмы и условия разных лотов не считаются одинаковыми. Скидка не прогнозируется.
- Значения свыше 1 млрд ₽ не показываются как исторический ориентир до проверки.
  Это технический фильтр, а не доказательство ошибки каждой большой закупки.
- Запрос цены открывает черновик в почтовой программе. Сайт самостоятельно письма не отправляет.
- Есть короткий список, сравнение до трёх компаний и CSV выбранных поставщиков.

## Исправления поиска и CSV
- Текстовый поиск не требует присутствия компании в первых 300 записях категории:
  это ошибочно исключало специалистов. Категория проверяется по профилю.
- В каталоге сохранено до 32 текстовых примеров на компанию/категорию вместо 4.
- Регрессия ремонта автоэвакуатора проверена: выдача содержит компании
  с автоэвакуаторами в описании опыта, а не общий ремонт приборов.
- Веса CatBoost сохранены. Новый показатель ML-качества не заявляется.
- Активность компании суммируется по категориям, а не перезаписывается последней.
- До двух повторов временных API-ошибок, таймаут запросов, четыре параллельных запроса.
- Остановка и продолжение не теряют строки. Неисправный бюджет/ИНН отмечается ошибкой.
- CSV-выгрузка защищена от интерпретации исходных строк как формул.

## Архитектура и данные
React → локальный /api/search → тот же собранный Cloudflare Worker →
SQLite с адаптером D1 → экспортированные деревья CatBoost → карточки / CSV.
Serving-профили построены из предоставленного архива 2024–2025.
CSV 2026 года используются только как запросы, не для обучения.
В готовом пакете интерфейс обращается к локальному API.
Ссылки компаний открываются только по действию пользователя.

cloudflare/generated/local.sqlite — локальная база; её не следует публиковать
в публичном GitHub. Публичный Worker/D1 не обновлялся.
Будущая публикация потребует синхронного обновления frontend, Worker и serving-данных.

## Проверки и воспроизведение
Frontend: pnpm install --frozen-lockfile; pnpm typecheck; pnpm build:local.
Worker: pnpm install --frozen-lockfile; pnpm typecheck.
Из корня: node scripts/build-local.mjs; node --test .local-build/core.test.mjs;
node scripts/check-integration.mjs.
scripts/check-browser.mjs проверяет интерфейс в Chrome на реальных присланных CSV.
Нужны Playwright и Chrome; при необходимости задайте PLAYWRIGHT_MODULE_PATH и CHROME_PATH.
Результаты проверок и реальные CSV-рекомендации находятся в `qa/` готового локального пакета; они не входят в публичный репозиторий.

Восстановление serving-базы из исходных трёх CSV 2024–2025:
python backend/build_local_data.py --data-dir /путь/к/CSV
Нужны pandas и numpy; переобучение и CatBoost для этого шага не нужны.
