# RLTTTSK — рекомендации поставщиков

[Сайт](https://romantamrazov.github.io/RLTTTSK/) · [Репозиторий](https://github.com/RomanTamrazov/RLTTTSK)

Закупщик вводит предмет закупки, ОКПД2 или ИНН в одну строку. Сервис находит похожие профили компаний и ранжирует их CatBoost-моделью. Карточка показывает опыт, причины попадания в выдачу и источник данных. Балл модели сравнивает кандидатов **внутри запроса**; это не вероятность победы.

## Как устроено

- `frontend/` — React/Vite сайт из макета команды, публикуется GitHub Pages.
- `cloudflare/` — публичный Cloudflare Worker с экспортированными деревьями CatBoost и поиском по D1.
- `backend/` — подготовка данных через pandas, обучение, локальный Python API и экспорт для Cloudflare.
- `cloudflare/generated/model.json` — обученные деревья, внесённые в Git. `cloudflare/generated/data.sql` — локально генерируемый импорт для D1, не публикуется в Git из-за размера. Исходные CSV и артефакты Python также остаются локальными.

В обучении положительной меткой служит записанный победитель электронной площадки ЭМ, а остальные участники её закупки — сравниваемые кандидаты. Записи АИС ГЗ расширяют поисковый каталог и подтверждают, чем компания занималась; они не подменяют метки победы в обучении. Небольшой пул проверенных компаний Портала поставщиков добавлен в те категории, где локальных кандидатов было мало. Отсутствие истории ЭМ показывается в объяснении.

Модель учитывает прошлые участия и победы компании в целом, в разделе ОКПД2 и у того же заказчика; давность активности; соответствие разделу; сходство текста с опытом; цену закупки, если она передана. Исторические признаки при обучении строились только по событиям до оцениваемой закупки. На отложенных закупках 2025 года Hit@1 составил **65,44%**, а на срезе со скрытой историей — **39,15%**. Это оценка ранжирования известных участников, а не гарантия нахождения всех подходящих компаний на рынке.

## Локальная разработка сайта

```bash
cd frontend
npm ci
npm run dev
```

Адрес API берётся из `frontend/public/config.json`. В репозитории указан опубликованный Worker. Для локального Worker поменяйте поле `apiUrl` на `/api`; Vite проксирует его на `http://localhost:8787`. Запустите Worker из `cloudflare/` командой `npx wrangler dev --remote`, чтобы использовать опубликованную D1.

## Обучение и экспорт модели

Нужны Python 3.11+, зависимости `backend/requirements.txt` и три исходных файла `Извещения_24-25.csv`, `Поставщики_24-25.csv`, `ТРУ_24-25.csv`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
python backend/prepare_catboost_data.py --data-dir /путь/к/исходным/csv
python backend/train_catboost.py
python backend/export_cloudflare.py
```

Экспорт создаёт `cloudflare/generated/model.json` и `cloudflare/generated/data.sql`. После обновления модели загрузите новый SQL в D1, затем опубликуйте Worker. Чтобы полностью заменить базу, создайте новую D1 и укажите её `database_id` в `cloudflare/wrangler.jsonc`; импорт рассчитан на пустую базу.

```bash
cd cloudflare
npm ci
npx wrangler d1 execute rltttsk-suppliers --remote --file generated/data.sql
npx wrangler deploy
```

D1 `rltttsk-suppliers` уже создана для аккаунта команды. Передайте сотрудникам только права доступа через Cloudflare; не копируйте токены в репозиторий. GitHub Pages публикует фронтенд из ветки `main` через `.github/workflows/pages.yml`.

## API

`POST /search` принимает, например:

```json
{"query":"ремонт автоэвакуатора ОКПД2 45.20.2 ИНН заказчика 7842019044","top_k":10}
```

`ИНН 7805198740` ищет одну компанию, `45.20.2` открывает раздел. Ответ включает разобранный запрос, число найденных кандидатов, рекомендации и причины ранжирования. Локальный Python API запускается командой `uvicorn site_api:app --app-dir backend --port 8000` и также предоставляет `POST /recommend` для списка переданных кандидатов.
