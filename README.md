# RLTTTSK — рекомендации поставщиков

[Сайт](https://romantamrazov.github.io/RLTTTSK/) · [Репозиторий](https://github.com/RomanTamrazov/RLTTTSK)

Закупщик вводит предмет закупки, ОКПД2 или ИНН в одну строку. Сервис находит похожие профили компаний и ранжирует их CatBoost-моделью. Карточка короткая: совпавший товар/услуга, цена или отметка «Цена по запросу», телефон/email и быстрые ссылки на проверку компании. В списке кандидатов видно, у кого контакт опубликован; поставщики с контактами поднимаются среди сопоставимых по предмету закупки. Балл модели сравнивает кандидатов **внутри запроса**; это не вероятность победы.

## Как устроено

- `frontend/` — React/Vite сайт из макета команды, публикуется GitHub Pages.
- `cloudflare/` — публичный Cloudflare Worker с экспортированными деревьями CatBoost и поиском по D1.
- `backend/` — подготовка данных через pandas, обучение, локальный Python API и экспорт для Cloudflare.
- `docs/RECOMMENDATION_LOGIC.md` — подробная документация признаков, источников, отбора кандидатов и метрик.
- `cloudflare/generated/model.json` — обученные деревья, внесённые в Git. `cloudflare/generated/data.sql` — локально генерируемый импорт для D1, не публикуется в Git из-за размера. Исходные CSV и артефакты Python также остаются локальными.

В обучении положительной меткой служит записанный победитель электронной площадки ЭМ, а остальные участники её закупки — сравниваемые кандидаты. Записи АИС ГЗ и строки ТРУ расширяют поисковый каталог: показывают конкретные товары и точные коды ОКПД2, с которыми связан участник; они не подменяют метки победы в обучении. Внешний пул содержит 30 проверенных профилей, в том числе выборочно добавленных поставщиков по слабым строкам тестовых файлов. Двадцать пять компаний не найдены в архиве 2024–2025 годов; их победы неизвестны. Новые компании не получают выдуманную историю побед.

Модель учитывает прошлые участия и победы компании в целом, в разделе ОКПД2 и у того же заказчика; давность активности; соответствие разделу; сходство текста с опытом по конкретным товарам; цену закупки, если она передана. Исторические признаки при обучении строились только по событиям до оцениваемой закупки. На отложенных закупках 2025 года Hit@1 составил **65,51%**, а на срезе со скрытой историей — **40,61%**. Это оценка ранжирования известных участников, а не гарантия нахождения всех подходящих компаний на рынке.

## Покрытие категорий поставщиками

Экспорт для сайта содержит 44 211 уникальных ИНН и 82 категории ОКПД2; более 90 тыс. записей «поставщик × раздел» содержат точные коды ОКПД2 из ТРУ. Отдельный внешний пул из 30 профилей покрывает подтверждённый ассортимент: рыба, медицинские изделия, продукты, ткани, семена, оборудование, клейкие ленты, слоёное тесто, перчатки, мебель, вакцины против гриппа и ремонт эвакуаторов. Для тестовых запросов о слоёном тесте, вакцине от гриппа 0,5 мл, многолетних травах, габардине, клеенаносящем станке, дижонской горчице, корнишонах и оливках база теперь возвращает минимум три проверенных профиля. Один поставщик может иметь несколько отдельных товарных предложений; сайт показывает именно подходящее запросу. Число профилей не гарантирует такое покрытие для любого нового запроса.

## Обогащение компаний

Проверенные по ИНН наименования, регионы, ОКВЭД и категории МСП берутся из [открытого ежемесячного реестра ФНС](https://www.nalog.gov.ru/opendata/7707329152-rsmp/). Срез от 10.09.2026 дал совпадения для **26 378 из 44 187** ИНН исторического пула. В репозитории хранится только это пересечение, а не исходный архив ФНС. Дата среза показана в карточке. Отсутствие компании в реестре МСП **не означает**, что компания закрыта: реестр охватывает только субъектов МСП.

Для валидных ИНН архивных поставщиков экспорт также добавляет последнюю активность в закупках 2024–2025, число наблюдаемых лотов и ссылки на Портал поставщиков и публичную карточку Saby по точному ИНН. Прямой URL ЕГРЮЛ с `?query=ИНН` не запускает поиск. Кнопка «Проверить ЕГРЮЛ» теперь отправляет один запрос к открытому поиску ФНС через локальный Worker и показывает найденное название, ОГРН/ОГРНИП и дату регистрации прямо в карточке. Ссылка на официальный сайт остаётся для получения выписки; публичная карточка Saby открывается сразу по ИНН. Свежесть проверяемых публичных контактов ограничена последними 36 месяцами и помечена датой проверки; архив закупок заканчивается 31.12.2025.

Проверенные рабочие контакты лежат в `backend/artifacts/supplier_contacts.csv` и `backend/artifacts/external_supplier_pool.csv` с адресом источника и датой проверки. У всех 30 компаний внешнего пула есть опубликованные контакты. Отдельно в `supplier_contacts.csv` лежат ещё 11 проверенных записей; девять из них относятся к компаниям внешнего пула, две добавляют прямые контакты историческим поставщикам. Среди остальных архивных поставщиков охват гораздо ниже: при отсутствии телефона или почты список показывает «Проверить», а карточка даёт ссылки на поиск по ИНН в Saby Profile, СПАРК и Портале поставщиков. СПАРК и Saby Profile / Trade рассматриваются как места проверки или платные API-интеграции; их закрытые базы в проект не копировались. Блок цены всегда показывает опубликованную цену либо «Цена по запросу», без выдуманной оценки. Для ремонта эвакуатора показывается только цена конкретной операции, не стоимость всего ремонта. Информация ФНС, контакты и публичные цены показываются закупщику отдельно; они **не входят в балл CatBoost**. Срез 2026 года нельзя подмешивать к признакам обучения на закупках 2024–2025 годов: это привело бы к утечке будущего. Для честного дообучения по внешним признакам нужны архивные срезы до даты каждого обучающего лота и новая временная проверка качества.

### Импорт проверенных карточек поставщика

Изучены [Import.io](https://www.import.io/) и [klesarev/yandex-parser](https://github.com/klesarev/yandex-parser). Они не подключены как автоматический фоновый сбор: Import.io требует API-ключ, а Yandex Parser требует Yandex XML Search API, регистрацию и разрешённый IP; он выдаёт ссылки/метаданные, а не гарантированные контакты/цены. Секретов доступа в репозитории нет. После получения выгрузки и ручной проверки её можно привести к `backend/artifacts/supplier_source_import_template.csv` и импортировать командой:

```bash
python3 backend/import_supplier_offers.py path/to/reviewed-suppliers.csv
```

Каждая строка должна иметь ИНН, дату проверки не старше 36 месяцев, ссылку HTTPS и `verified=true`. Для добавления нового поставщика также обязательны подтверждённое название и код ОКПД2. Затем обновите локальную базу экспортом `python3 backend/export_cloudflare.py && python3 backend/export_enrichment.py` и повторным импортом созданных SQL-файлов в локальную D1.

После скачивания ZIP со страницы ФНС обновление выполняется так:

```bash
python backend/enrich_fns.py /путь/к/data-10092026-structure-12052026.zip
python backend/export_enrichment.py
cd cloudflare
npx wrangler d1 execute rltttsk-suppliers --remote --file generated/enrichment.sql --yes
npx wrangler deploy
```

Портал поставщиков [предоставляет API](https://zakupki.mos.ru/public-api-access), но для токена нужна регистрация, а в опубликованном списке методов нет открытой массовой выгрузки телефонов и сайтов всех поставщиков. Публичные карточки портала используем выборочно для слабых категорий, когда подтверждены ИНН и предмет предложения.

## Локальное демо

Для демо сайт и сервис работают на ноутбуке: GitHub Pages, аккаунт Cloudflare и удалённая D1 не нужны. Worker использует локальную SQLite-базу Wrangler и экспортированную CatBoost-модель. Первый импорт каталога занимает несколько минут; дальше локальная база сохраняется между запусками.

```bash
./scripts/start_demo.sh
```

Откройте `http://127.0.0.1:5173`. Остановка — `Ctrl+C` в терминале. Пока скрипт работает, демо доступно в браузере на этом ноутбуке. После установки зависимостей интернет для поиска не нужен. Для показа другим людям с их устройств потребуется отдельно настроить публичный туннель.

Нужны локальные `cloudflare/generated/data.sql`, `cloudflare/generated/enrichment.sql` и `cloudflare/generated/model.json`, а также установленные зависимости. Если экспорты ещё не созданы:

```bash
python3 backend/export_cloudflare.py
python3 backend/export_enrichment.py
```

Один раз установите зависимости:

```bash
(cd cloudflare && npm ci)
(cd frontend && npm ci)
```

Локальная D1 хранится в `cloudflare/.wrangler/` и не попадает в Git. Чтобы заново импортировать данные, остановите сервис, удалите локальную папку `cloudflare/.wrangler/` и снова запустите скрипт.

## Локальная разработка сайта

```bash
cd frontend
npm ci
npm run dev
```

В режиме разработки `frontend/.env.development` направляет запросы на `/api`, а Vite проксирует их на локальный Worker на порту 8787. Production-сборка продолжает брать адрес из `frontend/public/config.json`.

## Обучение и экспорт модели

Нужны Python 3.11+, зависимости `backend/requirements.txt` и три исходных файла `Извещения_24-25.csv`, `Поставщики_24-25.csv`, `ТРУ_24-25.csv`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
python backend/prepare_catboost_data.py --data-dir /путь/к/исходным/csv
python backend/train_catboost.py
python backend/export_cloudflare.py
```

Экспорт создаёт `cloudflare/generated/model.json` и `cloudflare/generated/data.sql`. После обновления модели загрузите новый SQL в D1, затем опубликуйте Worker. Чтобы полностью заменить базу, создайте новую D1 и укажите её `database_id` в `cloudflare/wrangler.jsonc`; импорт рассчитан на пустую базу.

```bash
cd cloudflare
npm ci
npx wrangler d1 execute rltttsk-suppliers --remote --file generated/data.sql
npx wrangler deploy
```

D1 `rltttsk-suppliers` уже создана для аккаунта команды. Передайте сотрудникам только права доступа через Cloudflare; не копируйте токены в репозиторий. GitHub Pages публикует фронтенд из ветки `main` через `.github/workflows/pages.yml`.

## API

`POST /search` принимает, например:

```json
{"query":"ремонт автоэвакуатора ОКПД2 45.20.2 ИНН заказчика 7842019044","top_k":10}
```

`ИНН 7805198740` ищет одну компанию, `45.20.2` открывает раздел. Ответ включает разобранный запрос, число найденных кандидатов, отметку о наличии контактов, рекомендации и цену либо запрос коммерческого предложения. Локальный Python API запускается командой `uvicorn site_api:app --app-dir backend --port 8000` и также предоставляет `POST /recommend` для списка переданных кандидатов.
