# RLTTTSK — рекомендации поставщиков

[Сайт](https://romantamrazov.github.io/RLTTTSK/) · [Репозиторий](https://github.com/RomanTamrazov/RLTTTSK)

Закупщик вводит предмет закупки, ОКПД2 или ИНН в одну строку. Сервис находит похожие профили компаний и ранжирует их CatBoost-моделью. Карточка показывает опыт, причины попадания в выдачу, проверенные контакты и источник данных. Балл модели сравнивает кандидатов **внутри запроса**; это не вероятность победы.

## Как устроено

- `frontend/` — React/Vite сайт из макета команды, публикуется GitHub Pages.
- `cloudflare/` — публичный Cloudflare Worker с экспортированными деревьями CatBoost и поиском по D1.
- `backend/` — подготовка данных через pandas, обучение, локальный Python API и экспорт для Cloudflare.
- `docs/RECOMMENDATION_LOGIC.md` — подробная документация признаков, источников, отбора кандидатов и метрик.
- `cloudflare/generated/model.json` — обученные деревья, внесённые в Git. `cloudflare/generated/data.sql` — локально генерируемый импорт для D1, не публикуется в Git из-за размера. Исходные CSV и артефакты Python также остаются локальными.

В обучении положительной меткой служит записанный победитель электронной площадки ЭМ, а остальные участники её закупки — сравниваемые кандидаты. Записи АИС ГЗ расширяют поисковый каталог и подтверждают, чем компания занималась; они не подменяют метки победы в обучении. Внешний пул пока содержит только одну проверенную компанию, поэтому категории им не выровнены. Отсутствие истории ЭМ показывается в объяснении.

Модель учитывает прошлые участия и победы компании в целом, в разделе ОКПД2 и у того же заказчика; давность активности; соответствие разделу; сходство текста с опытом; цену закупки, если она передана. Исторические признаки при обучении строились только по событиям до оцениваемой закупки. На отложенных закупках 2025 года Hit@1 составил **65,44%**, а на срезе со скрытой историей — **39,15%**. Это оценка ранжирования известных участников, а не гарантия нахождения всех подходящих компаний на рынке.

На сайте можно загрузить CSV со списком закупок, получить рекомендации по каждой строке и скачать итоговый файл с исходными полями и поставщиками.

## Покрытие категорий поставщиками

Перепроверка текущего поискового каталога: 44 188 уникальных ИНН и 82 категории ОКПД2. Внешний пул содержит 1 уникального поставщика (ИНН 8911019868); он добавляет нового участника в разделы 03 и 10. После учёта этого пула в 5 категориях меньше 10 компаний, в 3 категориях — 10–29, в 7 категориях — 30–99. Следовательно, слабые и средние категории ещё не выровнены. Обогащение ФНС и ссылки на карточки улучшают проверяемость существующих компаний, но не увеличивают число поставщиков.

## Обогащение компаний

Проверенные по ИНН наименования, регионы, ОКВЭД и категории МСП берутся из [открытого ежемесячного реестра ФНС](https://www.nalog.gov.ru/opendata/7707329152-rsmp/). Срез от 10.09.2026 дал совпадения для **26 378 из 44 187** ИНН нашего пула. В репозитории хранится только это пересечение, а не исходный архив ФНС. Дата среза показана в карточке. Отсутствие компании в реестре МСП **не означает**, что компания закрыта: реестр охватывает только субъектов МСП.

Для всех **44 187** валидных ИНН экспорт также добавляет последнюю активность в архиве закупок 2024–2025, число наблюдаемых лотов и ссылки для ручной проверки контактов в ЕГРЮЛ и на Портале поставщиков. Это навигационные ссылки, а не выдуманные реквизиты. Свежесть проверяемых данных ограничена последними 36 месяцами: публичные контакты помечены датой проверки, а архив закупок заканчивается 31.12.2025.

Проверенные рабочие контакты лежат в `backend/artifacts/supplier_contacts.csv` с адресом источника и датой проверки. Если публичного контакта нет, карточка предлагает поиск по ИНН и не выдумывает телефон. Информация ФНС и контакты используются для показа закупщику; они **не входят в балл CatBoost**. Срез 2026 года нельзя подмешивать к признакам обучения на закупках 2024–2025 годов: это привело бы к утечке будущего. Для честного дообучения по внешним признакам нужны архивные срезы до даты каждого обучающего лота и новая временная проверка качества.

После скачивания ZIP со страницы ФНС обновление выполняется так:

```bash
python backend/enrich_fns.py /путь/к/data-10092026-structure-12052026.zip
python backend/export_enrichment.py
cd cloudflare
npx wrangler d1 execute rltttsk-suppliers --remote --file generated/enrichment.sql --yes
npx wrangler deploy
```

Портал поставщиков [предоставляет API](https://zakupki.mos.ru/public-api-access), но для токена нужна регистрация, а в опубликованном списке методов нет открытой массовой выгрузки телефонов и сайтов всех поставщиков. Публичные карточки портала используем выборочно для слабых категорий, когда подтверждены ИНН и предмет предложения.

## Локальная разработка сайта

```bash
cd frontend
npm ci
npm run dev
```

Адрес API берётся из `frontend/public/config.json`. В репозитории указан опубликованный Worker. Для локального Worker поменяйте поле `apiUrl` на `/api`; Vite проксирует его на `http://localhost:8787`. Запустите Worker из `cloudflare/` командой `npx wrangler dev --remote`, чтобы использовать опубликованную D1.

## Обучение и экспорт модели

Нужны Python 3.11+, зависимости `backend/requirements.txt` и три исходных файла `Извещения_24-25.csv`, `Поставщики_24-25.csv`, `ТРУ_24-25.csv`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
python backend/prepare_catboost_data.py --data-dir /путь/к/исходным/csv
python backend/train_catboost.py
python backend/export_cloudflare.py
```

Экспорт создаёт `cloudflare/generated/model.json` и `cloudflare/generated/data.sql`. После обновления модели загрузите новый SQL в D1, затем опубликуйте Worker. Чтобы полностью заменить базу, создайте новую D1 и укажите её `database_id` в `cloudflare/wrangler.jsonc`; импорт рассчитан на пустую базу.

```bash
cd cloudflare
npm ci
npx wrangler d1 execute rltttsk-suppliers --remote --file generated/data.sql
npx wrangler deploy
```

D1 `rltttsk-suppliers` уже создана для аккаунта команды. Передайте сотрудникам только права доступа через Cloudflare; не копируйте токены в репозиторий. GitHub Pages публикует фронтенд из ветки `main` через `.github/workflows/pages.yml`.

## API

`POST /search` принимает, например:

```json
{"query":"ремонт автоэвакуатора ОКПД2 45.20.2 ИНН заказчика 7842019044","top_k":10}
```

`ИНН 7805198740` ищет одну компанию, `45.20.2` открывает раздел. Ответ включает разобранный запрос, число найденных кандидатов, рекомендации и причины ранжирования. Локальный Python API запускается командой `uvicorn site_api:app --app-dir backend --port 8000` и также предоставляет `POST /recommend` для списка переданных кандидатов.

### CSV со списком закупок

Загрузите CSV с колонками `id`, `description`, `okpd2_code`, `customer_inn`, `start_price` (русские названия распознаются тоже). Для каждой строки сайт возвращает до пяти поставщиков и показывает их под соответствующей закупкой. Выгрузка сохраняет исходные столбцы, добавляет по одной строке на каждого рекомендованного поставщика: ранг, ИНН, название, причины, контакты и ссылки для проверки. Один файл — до 200 строк и 5 МБ; файл обрабатывается браузером, на сервер уходят только поисковые запросы строк.
